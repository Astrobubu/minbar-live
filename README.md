# Minbar Live

A browser-first local web app for Arabic ↔ English sermons in GCC venues and personal recordings. Requires Node 22 or newer. Start with `npm install`, copy `.env.example` to `.env`, then `npm start`. Local default: http://localhost:4310. The standard OpenAI key remains on the server. `APP_ACCESS_TOKEN` enables host access to billable routes; an account with a verified active subscription can also pass this gate. Session owner tokens or the owning signed-in account authorize private recordings and room controls.

The clearly labelled demo runs without credentials. Actual microphone transcription uses WebRTC and `gpt-live-transcribe`, client-side speech activity commits, then one server translation per committed item through Responses. SSE shares each final translation with attendees. English input translates to Arabic and vice versa. Use Android for phone testing; microphone access needs localhost or HTTPS. A loopback QR works only on the same machine; configure a reachable HTTPS `PUBLIC_BASE_URL` for real attendees.

Personal recording upload accepts WAV, WebM, MP3/MPEG, MP4/M4A and AAC; max 25 MB. AAC import requires server-side ffmpeg (`FFMPEG_PATH` optionally overrides its executable), converts a temporary copy, and preserves the uploaded original. Stored recordings are owner-only, downloadable/deletable, retained seven days by default (`RECORDING_RETENTION_DAYS`). Retention removes audio, not transcript text. `.data` contains sensitive transcripts, accounts and recordings: locally stored JSON is not encrypted. Transcript exports work; grounded insights require a project key.

Email/password registration, sign-in, sign-out and account-owned session access are implemented locally. Passwords use salted scrypt hashes; login cookies are HttpOnly and SameSite=Strict, and Secure with an HTTPS public origin. This is a local account store, with no email verification or password recovery. Optional Stripe checkout and signed webhook subscription updates exist; checkout requires all three Stripe settings plus an HTTPS `PUBLIC_BASE_URL`. No payment service was activated or live payment exercised in this work. Request allowances and session-duration limits exist, but they are not provider-cost metering or a complete billing reconciliation system.

Stable venue/speaker profiles are available through the API: signed-in owners can create/update profiles and attach owned profiles when creating sessions. Public profile detail lists public venue sessions only. The account page provides profile creation/editing, room creation provides profile selection, and permanent public profile pages link to venue sessions.

`/diagnostics.html` provides a labelled browser verification page for a selected local audio file or microphone. It exercises real WebRTC, audio relay and GPT-Transcribe double-checks; selected audio is sent to the configured provider and is not archived by this test. Its existence is not proof of a completed browser/device test. Use a connected Android device for physical microphone verification and a second listener to check playback.

Quran reference matching uses all 6,236 verses of **Tanzil Quran Text (Simple, Version 1.1)**, stored verbatim including its copyright notice. [Tanzil Project](https://tanzil.net/) licenses verbatim copies under its [terms](https://tanzil.net/docs/Text_License). Normalization exists only in a derived in-memory search index. Five-token exact normalized phrases are annotated only when unique in the corpus. The numeric evidence score denotes lexical equality, not calibrated religious certainty. Short verses, paraphrases, cross-segment quotes, ASR errors and English source references can remain undetected. Generated Arabic translation is never used as Quran evidence. Hadith wording creates an explicit review queue; no unverified reference or grade is generated.

`npm test` runs corpus matching and security/integration tests. `npm run benchmark` uses the four explicitly named local recordings and 10-second derived clips, compares completed-file requests separately from paced realtime streams, and records actual response/access errors in ignored `benchmark-results`. Benchmarks make billable API calls and require the explicitly supplied recordings and ffmpeg. No gold transcript is available, so WER and a reliable accuracy ranking cannot be reported. See [benchmark evidence](docs/benchmark-report.md) for engine versus application results and the known sentence-chopping failure, and [research](docs/research.md) for sourced decisions and corpus options.

API: config; authentication and account archive; billing status/checkout/webhook; public session discovery; create/detail/update sessions; owner demo/segments/realtime/audio/verification; private recording GET/DELETE; export; insights; public QR; SSE snapshots/segments/revisions/audio/status. Translated browser speech waits for double-checked items (or labelled demo samples). Audio-window double checks can supersede provisional captions; this label means another model pass, not human approval or guaranteed correctness. Physical Android microphone capture, public HTTPS access, interrupted-network recovery, many-attendee audio distribution and bilingual quality review remain unverified. No hosted deployment is included.

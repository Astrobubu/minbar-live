# Minbar Live

A browser-first local web app for Arabic ↔ English sermons in GCC venues and personal recordings. Requires Node 22 or newer. Start with `npm install`, copy `.env.example` to `.env`, then `npm start`. Local default: http://localhost:4310. The standard OpenAI key remains on the server. `APP_ACCESS_TOKEN` enables host access to billable routes; an account with a verified active subscription can also pass this gate. Session owner tokens or the owning signed-in account authorize private recordings and room controls.

The clearly labelled demo runs without credentials. Actual microphone transcription uses WebRTC and `gpt-live-transcribe`, client-side speech activity commits, then one server translation per committed item through Responses. SSE shares each final translation with attendees. English input translates to Arabic and vice versa. Use Android for phone testing; microphone access needs localhost or HTTPS. Share links and QR codes use `PUBLIC_BASE_URL`; when unset it follows `HOST`/`PORT`. On a local network start with `HOST=0.0.0.0` and the share panel uses this machine's LAN address, so phones on the same Wi-Fi can read over plain http (listeners need no microphone). Open the khatib console via `localhost`, not the LAN address. Configure a reachable HTTPS `PUBLIC_BASE_URL` for real attendees.

Personal recording upload accepts WAV, WebM, MP3/MPEG, MP4/M4A and AAC; max 25 MB. AAC import requires server-side ffmpeg (`FFMPEG_PATH` optionally overrides its executable), converts a temporary copy, and preserves the uploaded original. Stored recordings are owner-only, downloadable/deletable, retained seven days by default (`RECORDING_RETENTION_DAYS`). Retention removes audio, not transcript text. `.data` contains sensitive transcripts, accounts and recordings: locally stored JSON is not encrypted. Transcript exports work; grounded insights require a project key.

Email/password registration, sign-in, sign-out and account-owned session access are implemented locally. Passwords use salted scrypt hashes; login cookies are HttpOnly and SameSite=Strict, and Secure with an HTTPS public origin. This is a local account store, with no email verification or password recovery. Optional Stripe checkout and signed webhook subscription updates exist; checkout requires all three Stripe settings plus an HTTPS `PUBLIC_BASE_URL`. No payment service was activated or live payment exercised in this work. Request allowances and session-duration limits exist, but they are not provider-cost metering or a complete billing reconciliation system.

Stable venue/speaker profiles are available through the API: signed-in owners can create/update profiles and attach owned profiles when creating sessions. Public profile detail lists public venue sessions only. The account page provides profile creation/editing, room creation provides profile selection, and permanent public profile pages link to venue sessions.

`/diagnostics.html` provides a labelled browser verification page for a selected local audio file or microphone. It exercises real WebRTC, audio relay and GPT-Transcribe double-checks; selected audio is sent to the configured provider and is not archived by this test. Its existence is not proof of a completed browser/device test. Use a connected Android device for physical microphone verification and a second listener to check playback.

## Quran detection, retrieval and attribution

Spoken Arabic is checked against all 6,236 verses of **Tanzil Quran Text (Simple, Version 1.1)** (`data/quran-simple.txt`, verbatim with its copyright block). Detection is lexical and deterministic (no LLM, no network) and runs synchronously inside the segment request, normally in about 1 ms and never more than a few ms.

**How it works** (`lib/arabic.mjs`, `lib/quran-detect.mjs`, facade `lib/quran.mjs`): text is normalized (diacritics, Quranic marks, tatweel, hamza seats, alif maqsura, ta marbuta/ha, Persian letter forms, ligatures, punctuation). A unigram/bigram index over a tolerant skeleton of each word finds candidate regions in the whole Quran treated as one continuous word stream, so quotes that run across consecutive ayat need no special case. Each candidate is aligned with a banded local alignment that scores exact words, spelling variants (leading و/ف, medial alif) and fuzzy words (weighted edit distance: cheap for letters ASR confuses and for weak letters; short words must match exactly), and penalizes wrong, missing or extra words. A region is cited only if it has at least 4 aligned words (3 of them consecutive), a density of at least 60%, at least 60% of the touched verse(s) or at least 6 words, enough rarity (guards generic phrases) and is not a stock formula. A phrase that fits two different places about equally well (repeated verses and refrains) is **not** cited rather than guessed. A citation never crosses a surah boundary. Texts longer than 64 words (whole-recording uploads) are scanned in overlapping windows. A verse split across two segments is found by prepending the last 24 words of the two previous segments; such citations carry `spansPreviousSegment: true` and are attached to the later segment, whose `matchedText` covers only its own words.

**Formulas are ignored, not tagged**: the basmala, isti'adha, "الحمد لله (رب العالمين)", salawat, shahada, "إن الله", "يا أيها الذين آمنوا" on its own, "قال الله تعالى" and a few similar stock phrases never produce a citation (see `FORMULA_TEXT` in `lib/quran-detect.mjs`). They are still translated normally. Verses whose full text is repeated elsewhere (for example 55:13) are likewise left uncited. Hadith detection is unchanged (`reviewQueue`).

**Citation contract** (`segment.citations[]`, also on `revision` segments, in `snapshot` events and in exports):

```
{ kind: 'quran', reference: '2:255' | '2:255-256', surah, ayahStart, ayahEnd,
  surahName: { ar, en, meaning }, arabic: '<canonical Tanzil text of the ayah(s)>',
  translations: { en, ur, ... }, translationSources: { en: 'Saheeh International (Tanzil)', ... },
  matchType: 'exact' | 'approximate', confidence: 0..1, matchedText: '<spoken span that matched>',
  // additive extras: verses: [{ ayah, arabic }], sourceUrl, evidence: { normalizedTokenStart, normalizedTokenEnd, tokenCount },
  //   verificationStatus, sourceSegmentIds (double-checked), spansPreviousSegment }
```

`translations` only contains the room's target languages that have an established translation (en, ur, id, fr, tr; Arabic has none). Ranges join the ayah translations with a space. `matchType: 'exact'` means every aligned word was equal after normalization (alif spelling differences included) with no gaps. `surahName.en` is Tanzil's transliteration (for example "Al-Baqara"). `confidence` is a heuristic score of alignment quality and length, not calibrated certainty. Plain-text export adds `[Quran 2:255] <arabic>` and `[Quran 2:255 en] <translation>` lines.

**Translation context**: when a segment has a Quran citation, each per-language translation request also receives `quranVerses` (reference, spoken quoted words, canonical Arabic, established translation and its source) and an instruction to reuse the established wording for the quoted part only (`lib/translation.mjs`, `lib/openai.mjs`).

**Measured accuracy** (`tests/quran-detection.test.mjs`, reproducible, seeded). 40 real verses/ranges, 632 generated positive cases (plain, no diacritics, respelled, ASR-style letter swaps, dropped word, partial start/end, embedded in sermon sentences, split across 2-3 segments, plus harder cases: three combined edits, two dropped words, a substituted word, glued/split words, a 60-word sermon lead-in/out) and 71 negatives (41 non-Quran sermon sentences including formulas and hadith, 30 verses with shuffled word order): **precision 1.000** (0 wrong-verse citations, 0 false alarms) and **recall 0.995** (629/632; the 3 misses involve the ambiguous opening "يا أيها الذين آمنوا اتقوا الله" of 9:119 and 33:70). Standard set 422/424, hard set 207/208. Corpus sweep over 941 verses of 6+ words: 97% found clean, 97% with one swap and one dropped word, 0 wrong. Over all 6,236 verses: clean recall is 0% for verses under 4 words (by design), 81% for 4-5 words, 93% for 6-9 and 99% for 10+, with no wrong-verse citation; almost every miss is a verse repeated elsewhere in the Quran. These sets are generated from the corpus itself and the negatives were written by the implementer, so they measure robustness to the listed noise types, not accuracy on real khatib audio. Latency (warm, per segment, including tail handling): p50 about 0.6 ms, p99 about 3 ms, max about 8 ms on the development machine; the test fails above 20 ms p99. The only real Arabic in `benchmark-results/*.json` (25 unique strings) contains one genuine quotation of 2:235 ("إن الله يعلم ما في أنفسكم فاحذروا", approximate), found in 4 records; nothing else.

Known limits: paraphrase and translation-only quotes are not detected; verses under 4 words are not detected on their own; partially recited verses are cited as the whole ayah (see `matchedText` for the span); live ASR output with more than about one wrong word in three will be missed; English-source rooms get no Quran detection.

## Deploying on Vercel (shared state)

Set `KV_REST_API_URL` and `KV_REST_API_TOKEN` (Upstash Redis REST) and sessions, segments and live events are shared by every serverless instance: each session is its own set of keys (7-day TTL) and SSE listeners poll a per-room Redis stream. Without them the server keeps its single local JSON file. `OPEN_ACCESS=true` skips the host key and the localhost operator gate (owner tokens still protect each room). Accounts and recording archives remain per instance.
